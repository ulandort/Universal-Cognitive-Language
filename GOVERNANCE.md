# Governance and protocol evolution

This repository publishes a **UCL/1.0 normative profile** and reference tooling. The version is frozen for the published 1.0 profile. Backward-incompatible changes require a new version identifier, migration notes and conformance tests. Clarifications may preserve the version only when they do not alter already-valid packet semantics.

Contributions should include rationale, reproducible examples, interoperability test vectors where relevant, and a discussion of compatibility and security consequences. Maintainers should transparently record design decisions and changes. Apache-2.0 licenses the contributions under the repository's normal contribution process; contributors must have rights to submit their work. A contributor should not import proprietary or AI-provider secrets into test artifacts.

**No central authority is required to interpret an individual self-contained packet.** Governance here is about the official published specification and naming, not about approving arbitrary conversation content, declaring philosophical truths or authenticating participants. The maintainer roster and release-signing process should be established by the eventual GitHub repository owner; no person or organization is falsely named as an existing governing body.
